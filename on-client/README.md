# 내 보안 Agent 시작 틀 0.2.11

이 보안 Agent는 회사 직원이 자기 로그인 상태, 업무 앱 접속 결과, 최근 접속 기록과 보안 경보를 보는 보안 앱입니다. 13단계부터 22단계까지 이 프로젝트 하나로 화면을 채워 가며 완성합니다. 처음이라면 docs/GETTING_STARTED_STUDENT.md부터 읽습니다. 무엇을 왜 만드는지와 단계별 순서가 그 문서에 있습니다.

이 시작 틀을 받은 것만으로 단계를 통과하지 않습니다. 단계마다 docs/STUDENT_PROMPTS.md의 안내를 수업용 AI에 붙여 넣어 student/extension.mjs를 고치고, 화면에서 확인하고, 커밋한 뒤 ALEPH에 제출합니다. 제출하면 서버가 그 커밋의 코드를 받아 AI가 단계 과제 기준으로 읽고 판정합니다. 코드를 실행해서 판정하지 않습니다.

## 켜기

검수 환경은 Node.js 24.19.0이며 외부 npm 의존성이 없습니다. 이 폴더의 PowerShell에서 아래를 실행하고 PC 브라우저로 http://127.0.0.1:5189 를 엽니다. 자세한 켜기·끄기·다시 켜기는 docs/STUDENT_LAUNCH_GUIDE.md에 있습니다.

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1

npm start도 같은 서버를 켭니다. 기본 실행은 실제 회사 시스템(기존 엔진)에 연결되지 않은 상태입니다. npm run demo는 예제 자료로 화면을 보여 줄 뿐이며 실제 연결이나 성취가 아닙니다. npm run check는 student/extension.mjs의 문법만 확인합니다.

- .env.example에는 비밀 없는 설정만 있습니다.

## 13단계 저장점 · 사용자·기기·세션을 구분합니다

학생 코드 `student/extension.mjs`의 renderIdentity가 me·devices·sessions를 각각 처리합니다. 사용자 이름·ID, 현재 기기 이름·ID·보안 상태, 현재 세션 ID·상태, 기기·세션 목록을 입력에서 읽습니다. loading·ok·error와 예제 자료·연결 없음·확인 불가 모드를 구분합니다. 기기와 세션의 한국어 설명 옆에 원래 코드도 표시합니다. 새 입력마다 새 DOM을 만들어 이전 값이 오류 화면에 남지 않게 합니다.

### 적용 및 다시 실행

이 README가 있는 `on-client` 폴더의 PowerShell에서 `npm start`를 실행하고 http://127.0.0.1:5189 의 「보호 현황」을 엽니다. 기본 실행은 연결 없음이며 예제 확인은 서버 종료 후 `npm run demo`를 사용합니다. 예제 화면을 실제 연결 성취로 보지 않습니다.

직접 확인: 보호 현황·업무 앱·보안 기록 메뉴를 마우스 또는 키보드로 이동하고, 제공된 현재 계정 표시와 학생 표시를 비교합니다. 제공 탭 UI는 Tab으로 선택된 메뉴에 진입하고 방향키로 다른 메뉴로 이동합니다. 「다시 불러오기」 뒤 현재 값으로 교체되는지 확인합니다.

### 검증 결과 및 남은 확인

당시 Node.js 문법 검사와 모의 입력 18개 조합 점검을 통과했습니다. 사용자 보고로 공식 통과를 확인했습니다. 실제 계정·기기·세션 화면과 장애 재현은 이 개발 환경에서 직접 확인하지 않았습니다. 기기 보안 상태 표시는 악성코드 검사·치료 기능이 아닙니다.

## 14단계 저장점 · 선택한 업무 앱의 접속 판정을 표시합니다

renderDecision은 제공 UI의 studentData('decision')가 전달하는 status·mode·appId와 data의 appId·decision·reason·checkedAt을 사용합니다. idle은 앱 선택·접속 요청 안내, loading은 판정 확인 중, error는 요청 실패와 안전한 서버 메시지로 구분합니다.

판정 수신 시 접근 허용(allow), 접근 거부(deny), 추가 인증 또는 확인 필요(challenge), 판정 확인 불가(unknown)를 원래 코드와 함께 표시합니다. 목록에 없는 판정도 unknown으로 처리합니다. 판정 이유·시각·앱 ID를 표시하고 오류와 deny 판정은 다르다고 안내합니다. 요청 중·실패 화면에는 이전 판정 이유를 남기지 않습니다. 13단계 함수와 제공 UI는 유지했습니다.

### 적용 및 다시 실행

같은 `on-client` 폴더에서 `npm start` 후 「업무 앱」을 엽니다. 앱 하나를 선택하고 접근 요청을 누른 뒤 학생 영역의 앱 ID·판정·이유·시각을 확인합니다. 네 판정을 억지로 만들려고 정책이나 인증 정보를 바꾸지 않습니다. allow는 정책상 허용이며 실제 앱 접속 성공을 보장하지 않습니다. challenge는 이 앱이 추가 인증을 대신 수행한다는 뜻이 아닙니다.

### 검증 결과 및 남은 확인

Node.js 24.19.0 문법 검사와 모의 DOM 22개 점검 통과. 네 판정·알 수 없는 값, 각 요청 상태와 연결 모드, 실패와 거부 구분, 이전 이유 제거, HTML 형태 문자열의 텍스트 처리와 새 DOM 반환을 점검했습니다. 사용자 보고로 공식 통과를 확인했습니다. 실제 계정의 반환 결과와 브라우저·키보드 조작은 이 환경에서 미확인입니다.

## 15단계 저장점 · 내 접속 기록과 저장된 XDR 경보를 확인합니다

13·14단계는 사용자 보고로 공식 통과를 확인했습니다. 두 단계의 학생 함수는 원문 그대로 보존했습니다. 이번에는 `on-client/student/extension.mjs`의 `renderEvents({ status, mode, data?, error? })`만 구현했습니다. 제공 서버·public/app.js·판정 코드·인증 설정은 변경하지 않았습니다. 최상위 README의 1~12단계·보너스 기록은 보존합니다.

현재 구현: 제공 UI가 전달한 본인 기록 배열을 복사하여 at 기준 최신순으로 정렬합니다. 각 행에 사건 ID·원래 시각·종류·앱 ID·요약과 `data-student-event-id`를 표시합니다. 종류는 접속 기록(access)과 XDR 경보(xdr)를 구분하며, 앱 ID가 없으면 앱을 확인할 수 없다고 표시합니다. 원본 배열과 서버 기록을 수정하지 않습니다.

「기록 종류」「업무 앱」「접속 상태」선택 상자는 전체 값 all과 전달받은 원래 값을 사용합니다. 세 조건을 함께 적용하며 받은 배열 안에서만 필터링합니다. 표시 건수와 받은 건수를 구분하고 「사건 ID 상세」버튼으로 해당 기록의 상세를 엽니다. 상세에는 `data-student-event-detail`, 사건 ID·앱 ID, 근거와 규칙 각각의 ID·본문, access·session·device의 한국어 설명과 원래 코드를 표시합니다. unknown은 확인 불가(unknown)로 유지합니다.

새 입력으로 함수가 호출되면 새 DOM과 필터·상세 영역을 만들며 이전 선택을 초기화합니다. 필터 변경 시에도 옛 상세를 지웁니다. 빈 결과는 「표시할 기록이 없습니다」, 오류는 「기록을 불러오지 못했습니다: 서버 메시지」로 구분합니다. CONTRACT_MISMATCH는 응답 형식을 확인할 수 없다는 안내를 추가하며 이전 목록을 표시하지 않습니다. loading·error에서도 예제 자료·연결 없음·확인 불가 모드를 구분합니다. 모든 외부 문자열은 createElement와 textContent로 넣으므로 HTML 형태의 글도 본문 그대로 표시합니다.

### 적용 및 다시 실행

저장소 루트의 1~12단계 자료실과 13~22단계 로컬 앱은 실행 위치가 다릅니다. Node.js 24.19.0에서 저장소의 `on-client` 폴더를 PowerShell로 열고 실행합니다. 외부 npm 의존성 설치는 필요하지 않습니다.

```powershell
npm start
```

브라우저 주소는 http://127.0.0.1:5189 입니다. 기본 실행은 실제 엔진에 연결되지 않은 상태이므로 연결 없음·실패 안내가 나올 수 있습니다. 예제 화면을 보려면 Ctrl+C로 종료한 뒤 같은 폴더에서 `npm run demo`를 실행합니다. 예제 결과는 실제 계정의 기록이나 공식 성취가 아닙니다. 종료는 Ctrl+C입니다. 문법 검사는 같은 폴더에서 `npm run check`로 실행합니다.

첫 직접 확인: 「보안 기록」 메뉴에서 기록 종류·업무 앱·접속 상태 필터를 적용하고 해제하며 표시 건수와 행 내용이 일치하는지 확인합니다. 다음에는 기록의 상세 버튼을 눌러 근거·규칙·세 상태를 확인하고 「다시 불러오기」 뒤 옛 상세가 사라지는지 확인합니다. 빈 배열과 조회 실패는 서로 다른 안내여야 합니다. 실제 정책·인증 정보나 다른 사용자의 기록을 바꿔 시험하지 않습니다.

### 검증 결과 및 남은 확인

로컬 Node.js 24.19.0 문법 검사 통과. 모의 DOM에서 최신순 정렬·원본 배열 불변, 필터 10개 조합의 행/건수 일치, 상세의 근거·규칙·세 상태와 원래 코드, HTML 형태 문자열의 텍스트 표시, 재호출·필터 변경 시 상세 초기화, 빈 배열·일반 오류·CONTRACT_MISMATCH·loading 구분을 확인했습니다. 행별 상세 버튼만 있으며 실제 조치 버튼은 만들지 않습니다. renderEvents 앞뒤 학생 함수의 원문 보존도 확인했습니다. 이 결과는 모의 입력 점검이며 실제 브라우저 또는 공식 심판 판정이 아닙니다.

관측 범위는 앱 서버가 현재 등록 정보와 대조한 본인의 최근 40건입니다. 전체·생략 건수와 확인 시각은 제공 화면이 표시하며 학생 함수는 받은 목록만 처리합니다. 저장된 XDR 경보를 보여 줄 뿐 화면을 열 때 새로 탐지하지 않습니다. 과거 세션·기기의 unknown을 정상으로 바꾸지 않습니다. supportedActions가 비어 있어도 조치 기능을 만들어 넣지 않으며, 연결되지 않은 조치 안내는 16단계 범위입니다.

실제 계정·엔진 연결, PC 브라우저의 필터·키보드 조작, 실제 새로고침·조회 장애, 15단계 공식 통과는 사용자 보고로 확인했습니다. 유료 AI 호출·보안 조치·단계 제출은 실행하지 않았습니다. 자료실의 기존 배포·발급자·허용 경로·원본 API 설정은 이번 단계에서 변경하지 않습니다.

## 16단계 저장점 · 알림·빈 상태·실패·도움정보를 구분합니다

13·14단계 함수는 원문 그대로 보존했습니다. renderStatus를 구현하고 15단계 기록 상세에 미지원 조치 안내만 추가했습니다. 제공 서버·public/app.js·인증·판정 코드는 변경하지 않았습니다.

현재 구현: devices·sessions 각각의 불러오는 중·빈 목록·조회 실패·확인 불가를 구분합니다. 기기는 이름·ID·상태, 세션은 ID·상태를 한국어 설명과 원래 코드로 표시합니다. 오류는 자료 이름과 message를 표시하고 TIMEOUT 계열 코드는 시간 초과라고 안내합니다. 다시 시도는 위쪽 「다시 불러오기」를 사용자가 직접 누르도록 안내하며 자동 재요청은 없습니다. 새 입력으로 다시 렌더링되면 이전 오류를 유지하지 않습니다.

notifications는 항목마다 resource·code·message를 표시합니다. 빈 배열은 「주의할 알림이 없습니다」로 표시합니다. 세션은 현재 검증된 연결 하나이며 과거 세션 전체 목록이 아니라는 범위를 명시합니다. 등록 기기 조회는 본인 명의의 회수되지 않은 기기 최대 100개이고, 전체 건수·생략·확인 시각은 제공 UI가 담당합니다.

### 도움정보 표시와 복사

diagnostics는 제공 화면이 조회하여 전달하는 입력입니다. 학생 함수는 진단 API를 호출하지 않습니다. ok인 진단 결과에서 requestId·component·version·checkedAt·engine.mode·engine.code만 새 객체로 구성해 표시·복사합니다. 전체 응답이나 ai·인증 관련 추가 필드를 직렬화하지 않습니다. 비밀 형태를 포함할 수 있는 문자열은 원문 대신 숨김 안내를 사용합니다. 입력과 화면의 문자열은 textContent로 표시합니다.

학생 상태 영역 안의 버튼 이름은 정확히 「도움정보 복사」입니다. 유효한 결과가 없으면 비활성이고, 사용자가 누를 때만 안전한 객체를 JSON으로 복사합니다. 복사 성공·실패를 구분하며 권한 오류 뒤 자동 재시도하지 않습니다. 도움정보 조회 실패는 제공 화면의 「도움정보 불러오기」를 직접 누르도록 안내합니다.

### 미지원 조치

기록 상세의 data-student-event-detail 영역에 supportedActions가 전달된 경우만 각 값의 「<action> 미지원」 버튼을 표시합니다. 버튼은 disabled이며 클릭 처리기나 요청 전송이 없습니다. 「조치 실행 연결은 준비 중입니다」라고 설명하고 실제 조치에 성공했다고 표시하지 않습니다. 빈 배열에는 조치 버튼을 만들지 않습니다.

~~~

공식 도구는 기존 JSON을 덮어쓰지 않습니다. 파일이 이미 있으면 다른 새 이름을 선택합니다. 검사 결과 ok=true, checkedFiles=12, missing=[], mismatched=[]이면 선택한 커밋의 해당 원문들이 JSON에 포함된 것입니다. 이것은 검토 AI에 전달된 최종 입력이나 실제 운영 연결·공식 통과를 인증하지 않습니다. JSON은 커밋하지 않고 포털에서 같은 저장소·커밋과 함께 사용자가 직접 제출합니다.

### 연결 오류는 별도

NATIVE_HOST_DISABLED는 현재 실행에 계정 연결 호스트가 구성되지 않았다는 뜻입니다. tools/prepare-native-host.ps1은 존재하지만 npm start가 자동 실행하지 않습니다. 이 도구는 -Create 없이 검사만 하며 실제 준비는 문서의 담당자 절차를 따릅니다. 준비된 본인 설정은 start-alekov.ps1의 -NativeHostConfig로 명시해야 합니다.

ENGINE_NOT_CONNECTED는 SDP 연결이 없다는 뜻입니다. 기본 engine-adapter의 disconnected를 connected로 바꾸거나 예제 사용자·기록을 실제 값으로 꾸미지 않습니다. 담당자가 준비한 본인 SDP 설정과 현재 등록·권한이 필요합니다. 두 오류는 Vercel·Supabase 신규 생성으로 해결하지 않습니다.

### 이번 검증과 한계

Node.js 문법 검사와 공식 tar 생성기를 사용한 모의 압축 자료 7개 검사 통과: 정상 포함, 파일 누락, 내용 불일치, 커밋 불일치, gzip 손상, tar 헤더 손상, 다른 JSON 형식 거부. 실제 사용자 PC의 공식 JSON·권한·연결 성공·모델 호출과 재판정은 미확인입니다. 기능을 성공한 것으로 바꾸거나 판정기를 수정하지 않았습니다.
