# 케셰브 22단계 · 최종 커밋의 새 환경 재현 기록

이 문서는 13~21단계 결과를 **기존 작업 폴더와 분리된 새 빈 폴더**에서 다시 실행한 기록입니다. 모든 결과는 아래 1절의 기준 커밋 하나에서 얻었습니다. 서로 다른 커밋의 결과를 합치지 않았습니다.

이 기록은 학생 진술입니다. ALEPH 서버의 AI 검토는 이 문서와 코드 원문의 일관성을 읽는 것이며, 서버가 새 환경에서 명령을 실행해 재현한 것이 아닙니다. 따라서 AI 원문 검토 통과를 실행 성공 증명으로 해석하지 않습니다. 버전 표시와 지원 범위는 [릴리스 기록](STUDENT_RELEASE.md)에 있습니다.

## 2. 실행 환경

| 항목 | 이번 재현 | 기준 |
|---|---|---|
| 운영체제 | Linux 6.18 (개발용 격리 환경) | 수업 환경은 Windows. Windows 재현은 미확인 |
| Node.js | v22.23.4 | package.json 24.19.0, 실행기 허용 22~24. 하한 쪽 버전으로 확인 |
| npm | 10.9.9 | Node.js 동봉 |
| Git | 2.43.0 | — |
| 브라우저 | 실제 브라우저 대신 HTTP 요청과 jsdom 26.1.0 | PC 브라우저·키보드·클립보드 조작은 미확인 |

21단계 기록(Node.js v24.22.1)과 Node.js 버전이 다릅니다. Node.js 22에서는 시작할 때 `ExperimentalWarning: SQLite is an experimental feature` 경고가 한 줄 출력되었습니다. 제공 코드의 조치 저장소가 `node:sqlite`를 불러오기 때문이며, 서버 시작과 응답에는 영향이 없었습니다. 24.19.0에서 같은 경고가 나오는지는 확인하지 않았습니다.

## 3. 새 빈 폴더 준비와 원래 폴더 보존

원래 작업 폴더는 열거나 수정하지 않았습니다. 새 빈 폴더(파일 0개 확인)를 만들고 GitHub에서 받은 뒤 기준 커밋으로 고정했습니다.

```powershell
# 원래 작업 폴더 밖의 새 빈 폴더에서 실행합니다.
git clone https://github.com/rnjswnghl/keshev.git keshev-clean
Set-Location keshev-clean
git checkout --detach 2ed7dbf6cb9714600f078be634e5a5a55ce7ebb6
git status --short --ignored
```

| 확인 | 결과 |
|---|---|
| 받은 직후 미추적·무시 파일 | 0개 |
| on-client/.env | 없음 (기존 폴더의 설정 파일을 복사하지 않음) |
| on-client/node_modules | 없음 (on-client는 외부 의존성이 없으므로 설치 명령 실행하지 않음) |
| 개인 호스트 설정·자격 보관 폴더 | 복사하지 않음. 기본 실행은 연결 없음 상태 |
| 모든 실행 뒤 `git status --short --ignored` | 0개. 앱 실행이 프로젝트 폴더에 파일을 만들지 않음 |

비공개 저장소이거나 GitHub에 올리지 않은 경우에는 원래 폴더를 원본으로 삼아 `git clone "<원래 폴더 경로>" keshev-clean`으로 같은 절차를 따를 수 있습니다. 이번 재현은 GitHub 원격에서 받았습니다.

## 4. 실행·종료·재실행 (21단계 설명서 3절 순서)

21단계 설명서대로 on-client에서 문법 검사 뒤 기본 서버와 예제 서버를 각각 두 번 켜고 껐습니다. 다른 작업과 충돌하지 않게 이 검사에서만 `ON_PORT`로 임시 포트를 지정했습니다. 기본값 5189를 실제로 사용한 것은 아닙니다.

| 순서 | 명령(on-client) | 시작 신호 | 종료 |
|---|---|---|---|
| 문법 | `npm run check` | 오류 없이 종료 | — |
| 기본 1차 | `node src/server.mjs` (npm start와 같은 명령) | `케셰브 연결 확인: http://127.0.0.1:51891` | 종료 신호 뒤 포트 닫힘 |
| 기본 2차(재실행) | 같은 명령 | 같은 로그 | 포트 닫힘 |
| 예제 1차 | `node src/server.mjs --demo` (npm run demo와 같은 명령) | `케셰브 예제: http://127.0.0.1:51892` | 포트 닫힘 |
| 예제 2차(재실행) | 같은 명령 | 같은 로그 | 포트 닫힘 |

| GET 경로 | 기본 1차·2차 | 예제 1차·2차 |

| / | 200, 세 메뉴 문자열 포함 | 200, 세 메뉴 문자열 포함 |

## 7. 이동 가능한 구성

다른 PC로 옮길 때 필요한 것은 Git 저장소와 Node.js 22~24(권장 24.19.0)뿐입니다. 기본 실행에는 설치 명령·환경변수·설정 파일이 필요 없습니다.

| 구성 | 옮기는 방법 | 옮기지 않는 것 |
|---|---|---|
| 앱 코드·학생 코드·문서 | `git clone` 또는 아래 8절의 Git 번들 | — |
| 포트 등 비밀 없는 설정 | 실행 시 `ON_PORT` 또는 실행기 `-Port`. 이름은 .env.example 참고 (자동으로 읽지 않음) | 개인 .env |
| 계정 연결·AI 앱 연결 | 새 PC에서 담당자 안내에 따라 `-NativeHostConfig`, `-SdpHostConfig`로 새로 지정하고 승인 절차를 다시 진행 | 기존 호스트 폴더·자격 보관 파일·토큰 |
| 최상위 자료실(1~12단계) | `npm ci` 후 Vercel 환경변수 `SUPABASE_PUBLISHABLE_KEY`를 사용자가 설정 화면에서 직접 입력 | 키 값 자체 |

코드에는 개인 PC 경로가 없습니다. 개인 설정 경로는 실행할 때 인자로만 넘기고 Git·문서에 적지 않습니다.

| 학생 코드·문서·Git 이력 | 저장소 | 커밋 후 GitHub에 push. 추가로 프로젝트 밖에 `git bundle create "<프로젝트 밖 경로>\keshev.bundle" --all` | 새 빈 폴더에서 `git bundle verify` 뒤 `git clone <번들> keshev-restored`, 1절 트리 해시 대조 | 커밋하지 않은 변경은 백업되지 않음 |
| 기본·예제 실행 중 화면 상태 | 브라우저·서버 메모리 | 저장하지 않음 | 서버 재시작 후 「다시 불러오기」로 원천에서 재조회 | 종료하면 사라지는 것이 정상. 실행이 프로젝트에 파일을 만들지 않는 것을 3절에서 확인 |
| 조치 기록(SQLite) | 호스트가 명시적으로 넘긴 기존 DB 파일(절대 경로)에만 추가 테이블 생성 | 서버를 끈 상태에서 DB 파일을 프로젝트 밖 백업 폴더로 복사 | 서버를 끈 상태에서 원래 경로로 복사 후 시작 | 현재 이 프로젝트는 조치 미지원이라 DB가 없음. 이력 테이블은 수정·삭제 금지 트리거가 있어 내용을 고쳐 복원하지 않음. 실행 중 복사는 일관성 보장 안 됨. 저장소에 커밋하지 않음 |
| 계정·AI 연결 호스트 설정과 자격 보관 | 프로젝트 밖 호스트 폴더(제공 도구가 프로젝트 안 위치를 거부) | 백업·복사하지 않음 | 새 환경에서 담당자 절차로 다시 발급·승인 | 자격 정보에 만료가 있어 복사본이 유효하다는 보장이 없음 |
| 본인 SDP 기록·XDR 경보, AI 게이트 사용 기록 | 운영 측 원격 시스템 | 학생이 백업하지 않음(앱은 읽기만 함) | 운영 측 원천 | 학생 앱에서 원격 기록을 삭제·복원할 방법 없음 |
| 1~12단계 자료실 메모 | Supabase(운영 DB) | 학생 로컬 백업 대상 아님. data.json은 빈 견본 | Supabase 쪽 절차(미확인) | 이 단계에서 다루지 않음 |
| 원문 전달 JSON | 프로젝트 밖 출력 폴더 | 제출 기록으로 보관, 커밋하지 않음 | 해당 커밋으로 CLI를 다시 실행해 재생성 | 다른 커밋 제출에 재사용 금지 |

이번 재현에서 실제로 해 본 복원은 「GitHub에서 새 폴더로 받아 같은 커밋 실행」 하나입니다. Git 번들 생성·복원, SQLite 백업·복원은 절차만 적었으며 실행하지 않았습니다.

## 9. 시연·진술·원문 확인·실행 검증의 구분

| 종류 | 이 문서에서의 범위 |
|---|---|
| 실제 실행 검증 | 4·5절의 Linux 실행, HTTP 응답, jsdom 렌더링, 최상위 npm test |
| 예제(demo) 시연 | 5절의 「재현됨(예제 자료)」. 실제 계정 자료가 아님 |
| 계약 입력 확인 | 17~19단계 표의 값. 서버가 준 자료가 아니라 공식 입력 형태로 넣은 값 |
| 원문 확인 | 6절의 매니페스트·버전·비밀값 대조(코드 읽기와 해시 계산) |
| 학생 진술 | 이 문서 전체. ALEPH 서버는 이 진술을 읽을 뿐 재실행하지 않음 |
| 확인하지 않음 | Windows·PowerShell 실행기·PC 브라우저 조작, 실제 SDP·AI·OSV·조치 집행, 공식 22단계 판정 |

검사에 사용한 jsdom 도구와 스크립트는 저장소 밖 임시 폴더에 두었고 커밋하지 않았습니다. 프로젝트 의존성에 추가하지 않았습니다.
