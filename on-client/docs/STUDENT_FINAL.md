# 케셰브 마지막 총공세 · 완성본 기록

22단계 이후 「마지막 총공세」 1~7일차 권장 과제를 진행한 기록이며, 포털의 「완성 기록틀」 항목을 함께 채웠습니다. 이 문서는 새 점수나 판정을 만들지 않습니다. 마무리 제출은 저장소 주소와 40자리 커밋 번호로 합니다.

값은 네 가지로 나눠 적습니다.

| 표시 | 뜻 |
|---|---|
| **실측** | 이 환경에서 실제로 읽은 값(출처와 측정 시각 포함) |
| **예제** | `--demo`/`-Demo` 서버가 주는 설명용 값. 실제 자료 아님 |
| **미연결** | SDP 서버·계정·AI 게이트에 연결하지 않아 값이 없는 항목 |
| **확인 불가** | 읽으려 했으나 읽지 못한 값과 그 이유 |

작전 선택: 화면 틀 「관제 대시보드형」, 포장 형태 「포장 없이 내 PC에서 실행」(포털 권장 조합). 포장(`npm run package-app`)과 설치 프로그램은 만들지 않았습니다.

## 3. 핵심 기능 3개 (완성 기록틀 2)

### 핵심 기능 1 · 내 PC 점검 요약
- 제공된 부분: 측정 서버 `src/pc-status.mjs`(CPU 200ms 표본, 메모리, 디스크, 네트워크, Windows 방화벽·System/Application 경고·오류 24시간 집계), 읽기 전용 경로 `/api/pc/status`, 학생 허용 경로 목록, 제공 카드 「내 PC 상태」(`public/pc-status-view.mjs`)
- 내가 직접 개선한 부분(`student/extension.mjs`의 `buildPcPanel`·`refreshPc`):
  - `실측 n/6 · 확인 불가 m개` 요약을 붙였습니다.
  - 값마다 단위를 붙이고, 측정 시각과 출처(`local-pc`)를 표시합니다.
  - 확인 불가 이유를 한국어로 바꿔 보여 줍니다.
  - 직전 조회 대비 변화를 표시합니다.
  - 최근 조회 기록을 최대 5건까지 메모리에만 보관합니다.
  - SDP 연결 상태를 PC 조회 결과와 분리해 표시합니다.
  - 「다시 조회」 버튼, 대기 표시, 초점 유지를 넣었습니다.
  - 실패하면 다음 행동을 안내합니다.
- 실제 확인 결과(실측, Linux, 2026-10-30 11:36 KST): `실측 4/6 · 확인 불가 2개`, CPU 2.5%(200ms 표본), 메모리 0.7 GB / 7.8 GB 사용(9%), 디스크 29.5 GB 남음 / 전체 252.0 GB(12%), 네트워크 외부 연결 장치 1개·IPv4 1개, 방화벽·Windows 기록은 「확인 불가 · 이 운영체제에서는 읽지 않습니다」
- 잘못된 입력이나 연결 실패 때의 동작: 조회 실패 시 `role="alert"`로 오류 코드와 다음 행동을 표시하고 이전 값을 현재 상태로 보이지 않습니다. `NOT_ALLOWED`는 시작 틀 판 확인 안내, 출처가 `local-pc`가 아닌 응답은 실측으로 받지 않음, 모르는 이유 문자열은 원문을 노출하지 않음(합성 응답 검사)
- 근거: `on-client/student/extension.mjs`, 커밋 `994f23d`, 아래 4절 검사 기록

### 핵심 기능 2 · 업무 앱 접근 판정
- 제공된 부분: 앱 목록·접근 요청 UI, `POST /api/access`(같은 출처 요청만 허용), 판정 결과 전달
- 내가 직접 개선한 부분: renderDecision이 allow·deny·challenge·unknown을 원래 코드와 함께 구분하고, 요청 실패를 「접근 거부(deny) 판정이 아닙니다」로 따로 표시, 이전 판정 이유를 실패 화면에 남기지 않음(14단계)
- 실제 확인 결과: **예제**로만 확인. library allow, repository deny(기기 상태 확인 필요), approval challenge
- 연결 실패 때의 동작: 기본 실행에서 `ENGINE_NOT_CONNECTED`(SDP 미연결)
- 근거: 14단계 커밋 `376271f`, 누적 검사 24/24

### 핵심 기능 3 · 보안 기록과 경보
- 제공된 부분: 본인 최근 40건·저장된 XDR 경보 조회, 다시 불러오기
- 내가 직접 개선한 부분: renderEvents의 최신순 정렬, 기록 종류·업무 앱·접속 상태 필터 3개, 사건 상세(근거·규칙·상태 코드), 빈 목록과 조회 실패 구분(15·16단계)
- 실제 확인 결과: **예제**로만 확인. `event-01` 개발 저장소 접속 제한(access denied · session active · device unknown)
- 연결 실패 때의 동작: 「기록을 불러오지 못했습니다」와 오류 코드, 이전 목록 미표시
- 근거: 15단계 커밋 `d1e0c92`, 누적 검사 24/24

## 4. 시연 순서

한 번의 예제 실행으로 세 기능을 차례로 보여 줍니다. 앱 폴더(`on-client`)에서:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
```

1. **내 PC 점검 요약** — 「보호 현황」 → 학생 칸의 「다시 조회」를 두 번 누름. 예제 모드여도 이 칸의 값은 **실측**이며, SDP 줄은 「예제 모드」로 따로 표시됨을 보여 줍니다. Windows에서는 방화벽 세 프로필과 경고·오류 건수가 나오고, 그 건수가 침해 판정이 아니라는 문구를 짚습니다.
2. **업무 앱 접근 판정** — 「업무 앱」에서 세 앱을 차례로 요청해 allow·deny·challenge를 보여 줍니다(**예제**).
3. **보안 기록과 경보** — 「보안 기록」에서 필터를 바꾸고 `event-01` 상세를 엽니다(**예제**).
4. 마무리로 `Ctrl+C` 뒤 `-NoNativeHost`로 다시 켜서, 판정·기록 칸이 `ENGINE_NOT_CONNECTED`로 바뀌고 PC 요약은 그대로 실측됨을 보여 줍니다.

캡처를 포트폴리오에 쓸 때는 예제 화면에 「예제」라고 밝힙니다.

제로 트러스트 보안 Agent 「케셰브」를 직접 설계하고 구현했습니다.
- 13~20단계: 사용자·기기·세션 확인, 업무 앱 접근 판정, 보안 기록 표시를 만들어 ALEPH 판정 환경에서 코드 검토를 받았습니다.
- 마무리 단계: 내 PC의 CPU·메모리·디스크·네트워크를 실측해 보여 주는 점검 화면을 더했습니다. 읽지 못한 값은 「확인 불가」와 이유로 구분합니다.
- 실제 회사 서버 연결은 발급받은 개인 인증서가 있어야 열리도록 설계했으며, 이번 과정에서는 예제와 미연결 상태로 확인했습니다.
